# Marketplace


## Запуск

Нужен установленный и запущенный Docker Desktop.

```bash
cp .env.example .env
docker compose up --build
```

Если `.env` уже существует, обновите его по примеру вместо перезаписи.
Compose запускает PostgreSQL, применяет миграции и поднимает API на порту `8080`.
Пустой каталог возвращает `200` и `[]`:

```bash
curl http://localhost:8080/api/v1/products
```


Локальный запуск Go с PostgreSQL в Docker:

```bash
docker compose up -d pg migrator
go run ./cmd/http-server
```

Приложение само загружает `.env`. Можно указать другой файл и уровень логирования:

```bash
go run ./cmd/http-server -config-path .env -level debug
```

Логи выводятся в консоль и записываются в `logs/app.log` с ротацией. Каждый
HTTP-ответ содержит `X-Request-ID`. При SIGINT/SIGTERM сервер завершает обработку
текущих запросов и закрывает соединения с БД.
Инициализация разбита на `initLogger`, `initConfig`, `initServiceProvider` и
`initHTTPServer`, вызываемые из `initDeps`. Пул БД и файл логов регистрируются
в `github.com/Dokhoyan/common/pkg/closer`; после завершения HTTP-сервера
приложение вызывает `closer.CloseAll()` и `closer.Wait()`.


## Работа с БД

Каждый метод репозитория выполняет одну операцию: создать пользователя,
создать корзину, пометить пользователя удалённым или удалить его сессии.
Связанные операции объединяются в сервисе через `trManager.Do`, как в
`avito-pr-test`. Регистрация и удаление профиля выполняются в транзакциях:
при ошибке любого шага откатываются все изменения. Репозиторий получает
транзакционное соединение из контекста через `getConn`.

## Миграции

Таблицы создаются сразу со всеми полями и ограничениями: `users`, `products`,
`carts` / `cart_items`, `sessions`. Изменений таблиц через `ALTER TABLE` нет.

Формат логина и непустые имена проверяются в сервисном слое. В БД сохранены
`NOT NULL`, уникальность, внешние ключи и простые ограничения допустимых ролей,
цены, остатка, баланса и количества. Ограничения длины строк остаются в типах
`VARCHAR`; приложение проверяет длину до обращения к БД.

История миграций переписана для запуска с чистой БД. Уже применённые версии
Goose повторно не выполняет; существующие данные изменением SQL-файлов
не обновляются и не удаляются.

## API

Регистрация, вход и просмотр каталога публичные. Остальные маршруты требуют
`Authorization: Bearer <access_token>` и соответствующих прав.

| Метод | Путь | Тело JSON | Ответ |
| --- | --- | --- | --- |
| GET | `/api/v1/products` | — | `200`, массив товаров |
| GET | `/api/v1/products/{product_id}` | — | `200`, товар |
| POST | `/api/v1/products` | `name`, `price`, `stock` | `201`, товар |
| PATCH | `/api/v1/products/{product_id}` | `name` и/или `price` | `200`, товар |
| PUT | `/api/v1/products/{product_id}/stock` | `stock` | `200`, товар |
| POST | `/api/v1/products/{product_id}/stock/add` | `quantity` | `200`, товар |
| DELETE | `/api/v1/products/{product_id}` | — | `204`, без тела |
| POST | `/api/v1/users` | `name`, `login`, `password` | `201`, пользователь |
| POST | `/api/v1/auth/login` | `login`, `password` | `200`, токен и срок действия |
| POST | `/api/v1/auth/logout` | —, токен в заголовке | `204`, без тела |
| GET | `/api/v1/users/{user_id}` | — | `200`, свой профиль |
| PATCH | `/api/v1/users/{user_id}` | `name` | `200`, свой профиль |
| DELETE | `/api/v1/users/{user_id}` | — | `204`, без тела |
| GET | `/api/v1/users` | — | `200`, список для администратора |

```bash
curl -X POST http://localhost:8080/api/v1/products \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Клавиатура","price":20000,"stock":5}'
```

## Регистрация

```bash
curl -X POST http://localhost:8080/api/v1/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"Анна","login":"Anna_1","password":"example_password_123"}'
```

Ответ `201`:

```json
{"id":1,"name":"Анна","login":"anna_1","role":"user","balance":0,"created_at":"2026-11-10T10:00:00Z"}
```

## Назначение администратора

Сначала зарегистрируйте обычного пользователя через `POST /api/v1/users`.
Его профиль, пароль и корзина создаются обычной регистрацией. Затем назначьте
ему роль администратора служебным скриптом:

```bash
./scripts/grant-admin.sh anna_1
```

По умолчанию скрипт выполняет запрос через `docker compose exec` в сервисе `pg`.
PostgreSQL должен быть запущен, миграции применены. Запускать скрипт можно из любой
папки. Логин ищется без учёта регистра, удалённые аккаунты не учитываются.
Повторный запуск для администратора разрешён.

Для внешней БД задайте `PG_DSN` в окружении и установите `psql`, затем запустите
ту же команду. Скрипт не загружает `.env` в оболочку; в режиме Docker Compose
настройки берутся из конфигурации Compose и контейнера PostgreSQL.

Скрипт меняет только роль существующего активного пользователя. При неверном логине,
отсутствующем пользователе или ошибке БД завершается с соответсвующим кодом.

## Разработка и проверки

Нужен Go 1.27. Команды Makefile:

```bash
make build         # сборка bin/http-server
make test          # тесты с race detector и покрытием
make lint          # golangci-lint
make mock          # генерация моков mockery
make docker-up     # сборка и запуск Compose в фоне
make docker-clean  # остановка Compose без удаления данных
```

Версии инструментов закреплены в Makefile; вручную устанавливать их не нужно.

Интеграционный тест использует настоящую PostgreSQL, создаёт отдельную временную
схему и удаляет её после проверки. Пользователю БД нужны права на создание схем:

```bash
TEST_DATABASE_URL='postgres://boilerplate:boilerplate@localhost:5432/boilerplate?sslmode=disable' \
  make test
```

Без `TEST_DATABASE_URL` тест с БД пропускается. В CI он запускается с PostgreSQL.
Проверяются все ручки товаров, валидация, частичные обновления, параллельное
пополнение, переполнение, мягкое удаление, ссылки из заказов и откат миграции.
Тесты регистрации проверяют хеш пароля, профиль и пустую корзину, уникальность
логина при параллельных запросах, границы длины и откат при ошибке корзины.

Тесты третьего этапа проверяют права владельца и администратора, вход с неверными
данными, несколько сессий, срок 24 часа, выход, истечение токена, смену роли,
удаление аккаунта и сохранение сессии между экземплярами приложения.
